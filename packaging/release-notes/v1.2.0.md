- **Display modes.** New, optional `[Display]` section in `xml2-fix.ini`: `Mode=borderless` runs the game in a borderless window at your desktop's resolution and refresh rate (no mode switch, instant alt-tab, keeps running in the background), `Mode=windowed` in a normal centred window, `Mode=fullscreen` keeps exclusive fullscreen but at the desktop's refresh rate. `Width`/`Height` force a resolution; `Topmost` and `RunInBackground` do what they say.
- **Your desktop's resolution in Options → Video, and room for the rest.** The game writes its list into a table of 20 with no bounds check; a modern adapter offers more (24 on the development PC), and the ones past the 20th overwrite the default key bindings stored after it. With a `Mode` set the fix lists the adapter's sizes and the desktop's, trimmed to 20. `[Display] ResolutionList=all` gives the game a 64-entry table instead (after checking its code is the retail build's - otherwise the list is trimmed to 20, so it can never overflow) and fills it in every mode, the game's own included: every size the adapter offers, the desktop's, and in the borderless and windowed modes the common sizes of the desktop's aspect ratio plus half and three-quarter render-scale presets. `ResolutionList=game` keeps the game's own table and trims the list to it in every mode. `Width`/`Height` from the ini shows as the selected entry; a resolution still applies at the next start, with the game's own notice.
- **Frame rate and VSync.** The game caps itself at 60 fps with a busy-wait. `[Display] FrameRate=144` (or `refresh` for your desktop's rate, or `0` for no cap) switches that off and paces frames with a high-resolution timer instead, in any mode; the game's speed doesn't change with the frame rate. `VSync=1`/`0` sets the presentation interval in fullscreen; in the borderless and windowed modes, where Direct3D 8 has no usable vsync, `VSync=1` paces frames at the desktop's refresh rate (never above `FrameRate`).
- **All of it in the game's own menu.** *Options → Controls → Advanced* gets four rows under *FSAA*: Display mode, Frame rate (30 to 240, your desktop's rate, Refresh, Unlimited), VSync and Run in background, built with the game's own widgets and navigated, animated and drawn by the game. Accept writes only the rows you changed to `xml2-fix.ini`; the frame rate, Run in background and (in a window) VSync apply at once, the display mode after a restart - the panel says so. Revert to default puts the rows back to the stock values, and a row on its stock value removes its key on Accept, so the game is back to its own behaviour. `[Display] InGameOptions=0` hides the rows. On any build of `XMen2.exe` other than the retail one the panel is left exactly as it is.
- **For test tooling:** `[Test] InputPipe=1` opens the named pipe `\\.\pipe\xml2-fix-input`, through which a script presses keys (every screen reads them, the Advanced Options panel included) and saves screenshots of the frame the game just drew, without the game having the focus; its `status` reply reports the frames per second.
- Without a `[Display]` or `[Test]` section, and with the new rows left untouched, nothing changes about the window, the frame timing, the resolution list or the settings: the game runs as with 1.1.1, the four new rows in Advanced Options aside.

Install: copy `dinput.dll` into the folder that contains `XMen2.exe`. See the [README](https://github.com/ChronoRixun/xml2-fix#readme).
